Deploy ThreatLark where your data lives

Self-hosted by design. Run it in Docker, install it on a hardened Linux host, or add the browser extension. Your scan data stays inside your environment.

Deployment options

Three ways to run it

Pick the model that suits your environment; Docker and direct installs are kept at feature parity.

Fastest start

Docker

One command builds and starts a complete instance. Every scanner binary is baked into the image, so the host needs only Docker and Docker Compose.

Bare-metal / VM

Distro-aware installer

./install.sh detects Kali/Debian or a RHEL-family distro, installs prerequisites, generates secrets and a TLS certificate, builds, migrates and starts the app. Safe to re-run. Pairs with in-app one-click updates.

Chrome & Edge

Browser extension

A Manifest V3 companion (served from the app behind authentication) that runs tech-detect, SSL/TLS, port scan, WHOIS and CVE lookups against the current tab through your signed-in session, with no API keys stored in the extension.

Docker quick start

One command to a running instance

The simplest way to run a complete instance.

What the container does for you

  • All scanner binaries baked in: nmap (with raw-socket capabilities), sslscan, whois, Chromium for PDF export, massdns, nuclei with its full template set, and the bundled recon tools. No runtime downloads.
  • First-boot self-configuration: generates persistent secrets and a local CA→leaf TLS certificate once, applies database migrations and creates the first-run admin.
  • One data volume: the encrypted database, secrets, TLS material and backups live in a single named volume, so down/up keeps your data.
# build and start a complete instance
git clone <your-clone-url> ThreatLark && cd ThreatLark
docker compose up -d --build

# first-run admin password (forced change + MFA setup)
docker compose logs | grep -A4 FIRST-RUN

# then open https://localhost:4000 and sign in as "admin"

What you need

Docker needs nothing on the host but Docker itself; a direct install needs a few system tools.

Operations

Run it like production software

Day-two features are built in.

TLS out of the box

A local CA→leaf certificate is issued on first boot. Install your own CA-signed certificate from the admin panel with no restart, or terminate TLS at a reverse proxy.

Backup & restore

AES-256-GCM encrypted snapshots on demand or on a schedule, with optional push to remote SSH/SFTP targets. Restores require re-entering the admin password.

In-app updates

On supervised installs, one click backs up the database, pulls the new release, rebuilds and restarts. Docker deployments redeploy the image instead.

Corporate proxy support

Route outbound scanning and threat-intel traffic through your HTTP, HTTPS or SOCKS proxy, applied live. Raw TCP/UDP/ICMP tools such as nmap bypass it by nature.

Operational visibility

Live server health (CPU, memory, disk, database size) and background-scheduler heartbeats show whether scheduled scans and backups are running.

Offline licensing

Licence keys are signed tokens verified locally with no phone-home, so a licensed instance works on isolated networks.
